# Lantern

Lantern은 아직 범위와 성공 조건이 분명하지 않은 아이디어를 대화를 통해 구체화하는 요구사항 인터뷰 Skill입니다. 사람이 `$lantern`을 직접 호출하거나 Lantern 실행을 명시적으로 요청했을 때만 시작하며, 인터뷰가 끝나면 다른 사람이 바로 계획하거나 구현할 수 있는 수준의 명세를 제공합니다.

이 문서는 사람을 위한 사용 안내입니다. 에이전트가 따르는 정확한 동작 규칙은 [SKILL.md](SKILL.md)에 정의되어 있습니다.

## 어떤 요청에 사용하는가

다음과 같이 하고 싶은 일은 있지만 요구사항이 아직 충분히 정리되지 않았을 때 유용합니다.

- 새로운 기능이나 제품 아이디어의 목적과 범위를 정하고 싶을 때
- 기존 시스템의 개선 요청에 포함할 것과 제외할 것을 구분하고 싶을 때
- 여러 이해관계자가 다르게 해석할 수 있는 표현을 하나의 의미로 합의하고 싶을 때
- 구현 전에 제약 조건, 예외 상황, 성공 기준을 점검하고 싶을 때
- 다른 에이전트나 개발자에게 전달할 실행 가능한 명세가 필요할 때

Lantern은 단순히 질문 목록을 읽는 설문이 아닙니다. 앞선 답변을 바탕으로 현재 가장 불분명한 지점을 선택하고, 실제 실행 결과를 바꿀 수 있는 질문을 한 번에 하나씩 이어갑니다.

## 어떻게 요청하는가

기본 호출 형식은 다음과 같습니다.

```text
$lantern <정리하고 싶은 아이디어 또는 요청>
```

인터뷰 깊이는 세 가지 중에서 선택할 수 있습니다.

```text
$lantern --quick <요청>      # 빠른 정리, 최대 5라운드
$lantern --standard <요청>   # 기본 인터뷰, 최대 12라운드
$lantern --deep <요청>       # 더 엄격한 검토, 최대 20라운드
```

예시:

```text
$lantern --standard 고객이 출입 기록의 이상 징후를 조사할 수 있는 화면을 만들고 싶어.
```

사용 중인 클라이언트가 Skill의 slash invocation을 지원한다면 `/lantern`도 같은 방식으로 사용할 수 있습니다.

## 요청을 받으면 무엇을 하는가

Lantern은 다음 흐름으로 사람의 요청을 돕습니다.

1. 요청에서 이미 확인된 목적, 기대 결과, 제약, 비목표를 분리합니다.
2. 기존 코드나 문서가 중요한 요청이라면 질문하기 전에 확인 가능한 저장소 사실을 조사합니다.
3. 의도, 결과, 범위, 제약, 성공 기준과 기존 시스템 맥락의 명확도를 평가합니다.
4. 현재 실행에 가장 큰 영향을 주는 불확실성을 골라 질문을 한 번에 하나씩 합니다.
5. 선택지가 명확한 경우에는 각 선택의 영향과 tradeoff가 드러나는 구체적인 답변 후보를 제시합니다.
6. 숨은 가정, 경계, 반례 또는 현실적인 edge case를 최소 한 번 다시 점검합니다.
7. 충분히 명확해지거나 선택한 프로필의 최대 라운드에 도달하면 결과를 명세로 정리합니다.

인터뷰 중에는 단순한 사실과 사람의 결정, 아직 확인되지 않은 추론을 구분합니다. 저장소에서 안전하게 확인할 수 있는 내용을 사람에게 기억해 내라고 요구하지 않습니다.

## 최종적으로 받는 결과

요청에 필요한 항목만 골라 다음 내용을 포함한 `Clarified Specification`을 대화에 제공합니다.

- 요청의 의도와 기대 결과
- 포함 범위와 명시적인 비목표
- 후속 계획자 또는 구현자가 스스로 결정해도 되는 범위
- 기술, 정책, 일정 또는 호환성 제약
- 관찰하고 테스트할 수 있는 acceptance criteria
- 확인된 가정, 용어, edge case와 잔여 위험
- 기존 시스템을 조사한 경우 그 근거
- 사용한 프로필, 인터뷰 라운드 수와 최종 ambiguity 결과

이 결과는 후속 계획, 구현, 조사 또는 검토 요청의 입력으로 사용할 수 있습니다.

## 하지 않는 일

- 사람이 명시적으로 호출하지 않았는데 모호한 요청이라는 이유만으로 자동 실행하지 않습니다.
- 인터뷰 도중 코드를 구현하거나 production artifact를 수정하지 않습니다.
- 외부 CLI, terminal multiplexer, 별도 상태 저장소 또는 companion application을 요구하지 않습니다.
- 확인되지 않은 추론을 사람의 결정이나 사실처럼 기록하지 않습니다.
- 사람이 중단을 요청하면 인터뷰를 계속하지 않고, 현재까지의 내용을 간단히 정리해 종료합니다.

구현까지 이어가고 싶다면 Lantern이 명세를 제시한 뒤 별도의 요청으로 계획 또는 구현을 지시하면 됩니다.
