# SentraLab 프런트엔드 패턴

SentraLab 개발자가 새 프로젝트에서도 익숙한 방식으로 작업할 수 있도록,
반복되는 구현 기법과 구체적인 예제를 모은 프로젝트 소유 Skill입니다.
기존 제품의 기능이나 업무 규칙을 새 프로젝트의 기본값으로 복사하지 않습니다.
에이전트가 따르는 계약은 같은 디렉터리의 `SKILL.md`가 기준입니다.

## 구성 원칙

- **실행 가능한 기본 구성:** 도구, Provider, 공통 UI primitive와 검증된 유틸리티.
- **필요할 때 적용하는 패턴:** 폼, 목록, 상세 조회, 변경 요청, 날짜, 파일 업로드.
- **프로젝트에서 결정할 사항:** 권한, API, 검색 의미, 페이지네이션 방식, 시간대,
  입력 제한, 낙관적 처리, 승인 절차 등.

여러 제품에 같은 코드가 있다는 사실만으로 공통 정책이라고 판단하지 않습니다.
반복 사용 근거가 분명한 유틸리티는 포함할 수 있지만, 제품 규칙과 결합되어 있다면
그 구현 기법만 참고 예제로 남깁니다. 관련 판단은 `references/adoption.md`에 있습니다.

## 요청 방법

사용하는 에이전트에 이 Skill을 연결한 뒤, 이름과 구체적인 요청을 함께 전달합니다.
Skill 검색과 호출 방식은 클라이언트마다 다르며 OMP를 전제로 하지 않습니다.

```text
sentralab-frontend-patterns를 사용해서
이 프로젝트의 API 계약에 맞는 목록 화면을 만들어 주세요.
검색 조건과 페이지네이션 방식은 기존 명세를 먼저 확인해 주세요.
```

다음과 같은 요청에도 해당 주제의 참고 문서를 선택해서 적용할 수 있습니다.

- “기존 디자인에 맞춰 RHF/Zod 폼을 구현하고 Enter 제출과 오류 표시를 확인해 줘.”
- “읽기 전용 상세 Sheet를 추가하되, 캐시 데이터가 있으면 새 요청 중에도 보여 줘.”
- “이 편집 화면은 최신 정보와 revision이 필요해. 저장 실패 시 초안을 보존해 줘.”
- “업로드 API는 이미 있어. 파일 선택과 검증, 실패 후 재시도 UI를 연결해 줘.”
- “이 유틸리티가 템플릿 공통 코드인지, 제품 코드인지 검토해 줘.”

구체적인 기능 요청이 없으면 예제가 있다는 이유만으로 페이지, API, 폼을 만들지 않습니다.
Lantern 인터뷰도 자동으로 시작하지 않습니다.

## 예제를 사용하는 방식

각 참고 문서는 적용 조건, 적용하지 않을 경우, 필요한 제품 결정, 유지할 보장,
독립적인 코드 예제, 대안과 확인 시나리오를 제공합니다.

예제의 서비스 함수와 문구는 호출자가 넘기는 명시적인 경계입니다. 실제 기능에서는
프로젝트 서비스와 다국어 사전에 연결해야 합니다. 예제의 필드, 타입, 페이지네이션
방식, 간단한 레이아웃은 제품 요구사항이나 승인된 디자인을 의미하지 않습니다.
예제를 위해 가짜 API나 컴포넌트 갤러리를 기본 앱에 남기지 않습니다.

## 다른 Skill과의 관계

- `sentralab-react-ui-ux`: 접근성, 안정적인 비동기 UI, 데이터와 변경 요청의 안전성.
- `sentralab-frontend-patterns`: 요청된 기능에 위 원칙을 적용하는 조건부 구현 예제.
- `vercel-react-best-practices`: 위 계약을 보존하는 범위의 성능 개선.

프로젝트 요구사항과 명시적인 사용자 지시가 예제보다 우선합니다.
구체적인 우선순위는 프로젝트 루트의 `.agents/frontend-skill-precedence.md`에서
관리합니다. 이 정책은 특정 에이전트나 클라이언트에 종속되지 않습니다.
Skill은 패턴 적용 전에 이 파일을 읽도록 안내합니다. 다른 진입점에서는 사용하는
클라이언트의 프로젝트 지침에 이 파일을 참조하거나 작업 맥락에 명시적으로 포함합니다.
파일이 있다는 이유만으로 모든 에이전트가 자동으로 읽는다고 가정하지 않습니다.

## 프로젝트별 조정과 업데이트

이 Skill은 upstream에서 내려받은 파일이 아니라 템플릿이 소유하는 가이드입니다.
파생 프로젝트는 요구사항에 맞춰 이 Skill과 프로젝트 규칙을 수정하거나 제거할 수
있습니다. 루트 `AGENTS.md`, Vercel Skill, vendored SentraLab 플러그인을 수정할 필요는
없습니다. `skills-lock.json`은 CLI로 설치한 upstream Skill의 출처만 추적하며 이
프로젝트 소유 Skill을 배포하거나 자동 업데이트하지 않습니다.

공통 기법이 발전하면 변경 근거와 검증 결과를 검토한 뒤 다른 프로젝트에도 명시적으로
반영합니다. 중앙 레지스트리를 수정하거나 배포하는 작업은 별도의 범위입니다.
